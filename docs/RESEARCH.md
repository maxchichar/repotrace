# RepoTrace research — 2026-10-19

## Baseline and problem
Observed: the project has an empty README and two installed skill bundles; no application, manifests, tests, or deployment configuration. The user needs explainable contribution intelligence for public github.com repositories. Assumed audience: maintainers, engineering leads, and contributors comparing work within an explicit branch/time window. No private repositories, employment ranking, or claims of actual ownership.

## Source provenance
Official documentation was fetched from the public github/docs source repository on 2026-10-19 because direct docs.github.com and api.github.com requests returned proxy 403. After network propagation, the official commits, contributors, coauthors and PR pages were fetched successfully. The commits reference confirms the 3,000-file ceiling; the contributor reference confirms only the first 500 author emails are linked to GitHub accounts by that aggregate endpoint. The live Octokit path and a public repository analysis were subsequently verified; see VALIDATION.md.

- [Commits REST API](https://docs.github.com/en/rest/commits/commits): list branch commits with since/until, then fetch commit details/files. Paginate files, deduplicate SHA. Details have an API file ceiling (3,000); binary files/omitted patches have incomplete content. Stats describe churn, not surviving code, difficulty, or value.
- [Pull requests REST API](https://docs.github.com/en/rest/pulls/pulls): list closed PRs by base branch, filter merged_at by window. PR updated_at and merged_at differ: never stop scanning just because one updated page falls outside the merge window. Squash/rebase/merge strategies change commit correspondence. PR author is not necessarily every implementing author. Merged PRs are a separate metric, not added to commit or line counts.
- [Pagination](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api): follow next links; maximum per_page generally 100. Never label first-page counts complete. Every bounded crawl records caps/failures.
- [Rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api): inspect remaining/reset/retry-after; primary authenticated quota is commonly 5,000/hour vs 60 unauthenticated. Secondary limits also apply. Use sequential requests, explicit budgets, timeout, bounded retry, caching, and actionable 429 responses; no tight retry loops.
- [Contributor listing](https://docs.github.com/en/rest/repos/repos#list-repository-contributors): cached aggregate lists are discovery hints, not authoritative time-window metrics; anonymous author records and identity limits preclude treating the list as all people.
- [Multiple authors](https://docs.github.com/en/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/creating-a-commit-with-multiple-authors): Co-authored-by trailers in the final trailer block (separated from the subject/body by a blank line) express claimed shared authorship, not verified accounts or equal effort. RepoTrace uses an explicit equal fractional-credit policy per commit. Account IDs are strong links; name matching is not. Commit email is used only internally and is never exported. Unknown coauthors get opaque unresolved IDs and cannot be silently linked by display name.
- [CODEOWNERS](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners): configured reviewers are policy, not historical ownership or evidence of who wrote code. Ownership inference/blame is outside this release.
- [Merge strategies](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/about-pull-request-merges): merge commits can repeat changes from parents; exclude multi-parent integration commits from commit/churn metrics. Squashed history cannot reconstruct discarded individual work. Rebase changes SHAs. Branch history is what GitHub exposes, not every original contribution.

## Comparators inspected
- [GitHub Pulse](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/using-pulse-to-view-a-summary-of-repository-activity), verified through github/docs source: PR/issue summaries and top-15 default-branch commit activity (including coauthors). Adopt explicit period and direct GitHub evidence; extend beyond top-15; avoid presenting activity as value.
- [git-fame](https://github.com/casperdcl/git-fame), README retrieved: git-based authored/surviving line analysis with whitespace/move controls. Adopt explicit denominator and documented exclusions. RepoTrace measures changed lines, not surviving-line ownership; no claim of equivalence to blame.
- [gitinspector](https://github.com/ejwa/gitinspector), README retrieved: per-author statistics, timelines, source-file filters. Adopt readable timelines and explicit filtering; avoid hidden extension filters.
No competitor UI was rendered; no visual, accessibility, performance, or customer-outcome claims are made.

## Attribution decisions and reliability
1. Scope: selected branch is resolved to an immutable head SHA; committer timestamps (author date fallback is disclosed) filtered in UTC for commits; PR merge timestamps filtered independently. PR base branch is named and head snapshot timing disclosed. Force pushes, deleted branches, inaccessible commits, and changing PR lists prevent historical completeness guarantees.
2. Identity: canonical GitHub numeric account ID when provided; otherwise normalized email digest. A linked author email may connect a coauthor only when observed in this analysis and unambiguous. Names never merge accounts. GitHub noreply numeric IDs are usable identity hints only when they match observed accounts. Preserve unresolved identities. Report bot status from GitHub type or explicit [bot] suffix, not guessed from names.
3. Commit share: fractional units over observed non-merge commits, equal split across unique author/coauthor identities. Committer is not author. Anonymous authors remain in denominator.
4. Code-change share: additions + deletions in eligible files, fractionally shared by the same author set. Exclude known generated/vendor/lockfile paths by transparent heuristic; binary files and missing patches remain observable caveats. File renames identify path changes, not feature ownership. Report churn, not net lines or unique code.
5. PR share: one unit per merged PR to the reported opener; independent denominator. Never combine commit and PR percentages into a universal score. PRs without account identity remain unresolved.
6. Bots are included by default; toggling bot filtering recomputes all denominators. An empty denominator has 0% and no-data messaging, not NaN or inferred distribution. Rounding may make sums differ slightly from 100%.
7. Module attribution groups literal top-level paths. Commit messages/PR titles are evidence of stated intent, not proof of delivered features. Present linked commit/PR/file evidence; AI cannot invent features or ownership.
8. AI: opt-in server-side inference on bounded public metadata/file statistics (no raw source patches or emails). Model output must use known contributor IDs, valid evidence IDs, bounded impact bands, explicit uncertainty; invalid output rejected. Estimates are qualitative and never used for measured percentages. No model output when unconfigured; deterministic summaries remain available.

## Threats and unknowns
Untrusted repository text can contain prompt injection; model gets data only, no tools, no secrets, constrained JSON, and validated citations. SSRF prevented by accepting github.com owner/repo only and fixed upstream hosts. Public-only enforcement even with a privileged server token. Cost controls: bounded request/body/window/page/file/model budgets, TTL cache, in-flight deduplication, per-client/global quotas. Single-instance cache and rate limiter are not distributed production controls. No claims about deleted history, attribution fairness, labor, code quality, undocumented coauthors, or actual technical impact.
